# MidiAppBox メトロノームApp 磨き込み(ボリューム調整・テンポ1刻み)

まず CLAUDE.md を読み、全ルール(シェル実行の原則、教訓チェックリスト)に従うこと。
メトロノーム関連の経緯は docs/dev-log.md の Phase 7(7A〜7C)を読んでから着手すること。

## 背景

メトロノームApp(Phase 7C 完了済み)への小規模改善。本フェーズは **7D** とし、
完了時に docs/dev-log.md へ実施記録を追記、CLAUDE.md の「現在地」を更新する。
**Host API・ABI・共有 struct(hostapi_defs.h)の変更は行わない。App 内の変更のみ**で
完結させる。必要と判明した場合は実装せず停止して報告(Phase 8 で扱うか別途判断する)。

## 事前確認(このセッションが hpane.sh の初回)

CLAUDE.md「初回導入時の確認事項」を実施すること
(herdr tab list の JSON 確認 → ensure → echo hello テスト)。
問題があればパーサを修正して報告してから本作業に入る。

## タスク 1: テンポ刻みの変更(5刻み → 1刻み)

- 現在 BPM は ±5 でしか変更できない。1 刻みで調整できるようにする。
- UI 案を実装前に提示して承認を得ること。案には +1/-1 ボタン追加のほか、
  長押し・連打で加速するなどの操作性向上策があれば含める。
  制約: retained 描画モデルのスロット収支(rect/text 各 16)を案ごとに明記すること。

## タスク 2: ボリューム調整機能の追加

- まず調査して報告: クリック音の音量が App 内から既存 API だけで制御可能かを
  コードで確認する。特に以下の 2 経路を検証すること:
  1. `hostapi_tone_define` の level(0-100)— 拍音は 7C のトーンパレット経由の
     はずなので、App が slot 0(通常拍)/アクセント slot の level を変えるだけで
     成立する可能性が高い
  2. `hostapi_audio_set_volume` — 7A でマスター音量化されており、トーン出力にも
     効くかどうか(効くなら音量 UI はこちら 1 本で済む可能性もある)
- 両経路の実装箇所(実機 audio.cpp / Linux ミキサ)を確認し、どちらを採用するか
  根拠つきで報告 → 承認後に UI 案を提示 → 承認後に実装。
- どちらでも実現不可(Host API 変更が必要)と判明した場合は、理由と選択肢を
  報告して停止すること。

## 進め方・完了条件

- 実装前チェックポイント: (a) タスク 2 の調査報告 (b) UI 案(タスク 1・2)。
  承認後は Phase 完了まで自律的に進めてよい(CLAUDE.md のルールどおり)。
- 完了条件: Linux ホスト(SDL)と ESP32 実機の両方でビルドが通り、
  1 刻みテンポ変更と音量調整の動作確認ができること。
  実機確認はカメラ録画で行い、素材は `~/ビデオ/zenn-phase7d/` に残す。
- 回帰: metronome の既存機能(BPM/拍子/START/STOP/アクセント)、
  demo.wasm、アプリ停止後の free heap 一定(リークなし)を確認。
- コミットは両ホストでの動作確認後。dev-log 追記・現在地更新もコミットに含める。
  新たな教訓があれば CLAUDE.md の教訓チェックリストにも一行追加する。
