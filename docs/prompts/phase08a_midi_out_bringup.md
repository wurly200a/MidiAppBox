# Phase 8a: MIDI OUT 疎通確認（ハードウェア検証のみ）

## 目的

自作した MIDI OUT 回路（2SC1815 トランジスタドライブ、GPIO18 = UART1 TX）が
物理的に正しく動作することを、UM-ONE を介して確認する。

**このPhaseはHost API/ABIの変更を含まない。** WASMアプリからは呼び出さない、
native host 側の一時的な検証コードのみで完結させること。
既存の Host API を1文字も変更しないこと。

## 前提（回路構成）

- ドライブ元: GPIO18（UART1 TX を割り当て）
- UART パラメータ: 31250 bps, 8N1
- 論理反転が必要: `uart_set_line_inverse(UART_NUM_1, UART_SIGNAL_TXD_INV)`
  を UART 初期化直後に呼ぶこと。これを忘れると MIDI 信号が論理反転したまま
  出力され、受信機器が正しくデコードできない。
- 電源: 3.3V（5V ラインは未接続、本ボードでは使用不可）
- 接続構成: 自作 MIDI OUT 回路 → MIDI ケーブル → UM-ONE の IN → USB →
  PC 上の MIDI モニタ

## 進め方（承認ゲート）

1. **調査・実装方針レポートを先に提示すること。** コードを書く前に、以下を
   含む短い報告を出すこと：
   - 検証コードをどこに置くか（既存コンポーネント内 or 独立のテストタスク）
   - 既存の `app_tick` / audio / display の処理と競合しないか
   - 送信するテスト用 MIDI メッセージの内容（下記「テスト内容」参照）
   - ロールバック方法（このPhase専用コードをどう切り離すか）
2. 上記レポートに対して私が承認してから実装に進むこと。
3. 実装後、ビルド・書き込み・モニタは必ず `herdr` の pane 経由で実行すること
   （直接実行禁止）。build 用・flash 用・monitor 用に個別の named pane を
   作成し、`docs/workflow.md` §（該当セクション）のコマンド形式に従うこと。

## テスト内容

最小構成でよい。以下のいずれかを 1〜2秒間隔で送信し続けるだけの
シンプルなループとする：

- Note On (0x90, note=60, velocity=100) → 300ms 後 → Note Off (0x80, note=60, velocity=0)
- チャンネルは 1（0x90/0x80 のステータスバイトで固定）
- 無限ループでよい。停止条件は不要（目視確認後に電源を切って終了）

このメッセージ選択の理由：Note On/Off は UM-ONE 側の MIDI モニタソフトで
一目で正誤判定できる（ノート番号・ベロシティが表示されるため、
論理反転ミスや配線ミスがあれば「何も表示されない」または
「化けたバイトが表示される」という形で即座に分かる）。

## 確認方法

1. UM-ONE を PC の USB に接続。
2. PC 側で MIDI モニタを起動する（環境に応じて以下のいずれか）：
   - Windows: MIDI-OX
   - Linux: `aseqdump -p <UM-ONEのポート名>`（`aconnect -l` で事前にポート確認）
   - macOS: Audio MIDI設定 + MIDI Monitor アプリ
3. ESP32 側で本テストコードを起動し、UM-ONE の IN に MIDI ケーブルで接続。
4. モニタに Note On (note=60) → Note Off が 1〜2秒間隔で表示され続けることを確認。

## 成功条件

- モニタに正しい Note On/Off メッセージが連続して表示される。
- ノート番号・ベロシティが送信値と一致する（60, 100 / 60, 0）。
- 表示が途切れず、化けたバイトやランニングステータス起因の誤解釈が
  発生しない（数分間の連続観察で確認）。

## うまくいかない場合の切り分け（トラブルシュート順）

1. **何も表示されない**
   - `uart_set_line_inverse` の呼び出し漏れを疑う（最頻出）。
   - DIN の pin4/pin5 が逆になっていないか、テスターで導通確認。
   - UART のボーレートが 31250 になっているか確認。
2. **化けたバイトが表示される**
   - GND 共通化ができているか確認（自作回路の GND と ESP32 の GND が
     同一であること）。
   - 33Ω抵抗の値・配線に誤りがないか再確認。
3. **一部だけ表示される/たまに欠落する**
   - `app_tick` 実行時間が UART 送信をブロックしていないか
     （Phase 7C で確認済みの ~5ms 遅延要因と競合していないか）を確認。
   - このテストコードが display/audio と同じタスク上で動いていないか確認。

## スコープ外（このPhaseではやらないこと）

- Host API への `hostapi_midi_send` 追加（Phase 8 本体で実施）
- MIDI IN（TLP2361）側の検証（別Phaseで実施）
- WASM アプリからの MIDI 送信（Phase 8 本体以降）
- テンポ可変・複数ノート・和音などの複雑なメッセージ
