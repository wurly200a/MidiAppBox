# Zenn 連載記事の作成・更新(運用ルール)

連載「ESP32でWASMアプリを動かす」の記事作成・更新はこのファイルに従う
(指示がなくても自律的に進めてよい範囲を含む)。
記事作業を始める前に、本ファイル全体を読むこと。

## 概念の区切り(開発と連載の共通ルール)

- **編**: 連載のまとまり(story arc)。**各編の先頭の回=その編の入口**で、
  テーマ宣言・到達点・編内の読み方マップを持つ(まとめ記事という別階層は作らない)。
- **回**: 記事 1 本の単位。**フラット通番「第 N 回」**でタイトルに `(N)` を入れる。
  編はタイトルに入れず、入口の回と各記事の冒頭 1 行だけが名乗る。
- **フェーズ**: 開発の単位(Phase 5、6A、7B-fix 等)。1 フェーズ=1 回が基本だが、
  **回をまたがることもある**(逆に複数フェーズを 1 回に束ねることもある)。
- **記事は「回」の単位で作成する**。フェーズ完了 → 対応する回を執筆、が基本フロー。

## リポジトリと基本情報

- 記事リポジトリ: `~/project_doc/wurly-zenn-contents/`(Zenn CLI 管理)。
  記事は `articles/<スラッグ>.md`、画像は `images/`(命名 `<スラッグ>_NN.png`)。
- プレビューは `npx zenn preview`(ネットワークが要るのでホスト側 pane)。
- コミットメッセージは既存慣例に合わせる: `feat(articles):` 新規 /
  `docs(articles):` 加筆修正 / `refactor(articles):` 構成変更。
- GitHub 連携で push が Zenn への反映に直結する。**push は公開操作**として扱う
  (下記のスケジュール公開ルールに従っていれば push してよい)。

## 公開ルール(スケジュール公開・1 日 1 記事)

- **1 記事公開/1 日**になるよう、`published: true` + `published_at: "YYYY-MM-DD HH:MM"`
  (未来日時)でスケジュール公開する形で記事を作る。下書きのまま溜めず、
  公開日を割り当てて予約する。
- 公開日の割り当て(どの回を何日にするか)は**ユーザーと合意してから**設定する。
  合意済みのスケジュールに沿った修正・push は自律的に行ってよい。
- 動画は YouTube 埋め込み(URL)。**YouTube へのアップロードはユーザー作業**。
  記事側はプレースホルダにせず、URL をもらってから埋める(第 8 回の例: `youtu.be/...`)。

## 記事フォーマット規約

- frontmatter: タイトル `"ESP32でWASMアプリを動かす (N) <タイトル>"`、emoji 🎹
  (制作ノート系は🤖)、`type: "tech"`、topics は内容に応じて
  (esp32, wasm, wamr, rust, espidf が基本)。
- 冒頭 1 行(入口以外の回): 「本記事は連載…**<編名>**の第 N 回です」+編の入口へのリンク。
- **リンク規則**: 末尾の連載リストは「各編の入口+現行編の全回」のみ
  (過去の編は入口 1 行に集約)。本文中のインラインリンクは編をまたいでも
  直接その回へ(読者最優先)。冒頭の AI 注釈(`:::message`)は付けない。
- 編が増えるときも同じ型: 先頭の回=編の入口を新規に書き、
  末尾リストには過去の編の入口だけを足す。

## 記事作成フロー(フェーズ完了 → 記事)

1. ネタ元は docs/dev-log.md の実施記録+検証エビデンス(`~/ビデオ/zenn-phaseXX/`)。
2. 実測値は実施記録の数値をそのまま使い、計測条件(-Og, 160MHz, fast-interp 等)を明記。
3. 静止画は録画から ffmpeg でフレーム抽出し `images/<スラッグ>_NN.png` に配置。
4. 執筆 → プレビュー → **ユーザーレビュー** → 公開日を合意して `published_at` 設定 → push。
