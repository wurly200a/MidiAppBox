### 0-0. Linux ホストの画面キャプチャ(ユーザー指示による再挑戦)

**結論: 取れる。静止画・動画とも可能。** x11grab が黒くなるのは画面全体(ルートウィンドウ)を読むためで、
**ウィンドウ ID を指定して読む `xwd -id` / `import -window` なら SDL ウィンドウの中身が取れる**。

| 方法 | 結果(touch_demo、640×480) |
|---|---|
| `ffmpeg -f x11grab`(現行の `scripts/screen-*.sh`) | 黒(平均輝度 0.0002、68 色)。check-workflow と同じ |
| **`xwd -silent -id <win>`** → `convert` で PNG | **取れた**(平均 0.179、579 色。目視でタイトル・文字・ボタンを確認) |
| **`import -window <win>`**(ImageMagick) | **取れた**(xwd と同一の画像) |
| 動画: `xwd` を 10fps で連続取得 → `ffmpeg -framerate 10 -i f%04d.xwd` で h264 | **取れた**(xwd 1 枚 7ms、50 枚を 5.27 秒で取得 → 5.00 秒の mp4。途中のフレームも黒くない) |

- 環境: `XDG_SESSION_TYPE=wayland`、`DISPLAY=:0`(XWayland)、GNOME。`xwd` / `import` / `ffmpeg` は導入済み。
- ウィンドウの特定は **`midibox_host` の pid と `xdotool getwindowpid` の一致**で行う(同名のフレーム窓は mutter の pid)。
- check-workflow の時点では x11grab と GNOME Shell の D-Bus しか試しておらず、ウィンドウ単位の取得は試していなかった。
  Phase 6 / 7 の「スクリーンショット一式(Linux)」は、この経路(`import` 系)だったと考えられる(記録に方法が残っていない)。
- 注意: 動画のフレーム間隔は `sleep` による概算で、**UI の動作確認用**。タイミング測定には使わない。

**提案(ゲート 3、`scripts/` の変更)**:

1. `scripts/screen-still.sh`: x11grab をやめ、pid 一致で選んだウィンドウに `import -window` を使う。
2. `scripts/screen-rec.sh`: x11grab をやめ、`xwd -id` を 10fps で一時ディレクトリに連続保存する。Enter で止めたら `ffmpeg` で mp4 にまとめる。
3. 成功したら `docs/workflow.md` の §1-8「画面キャプチャの自動化は未解決」と §6.1 の `screen` ペインの説明、`docs/lessons.md` の該当項目を訂正する。roadmap U-12 は次の指示書作成時にクローズする。

**波及効果**: クリックの自動化(xdotool)が「どこに届いたか確認できないので信頼できない」とされていた件(lessons)は、
キャプチャで結果を確かめられるようになったので、**Linux での画面遷移の確認に xdotool のクリック + キャプチャを試す**(失敗しても実機の確認が正。0-5)。

### 0-1. 画面設計と描画スロットの予算表(指示書 a)

論理画面 320×240。**3 画面で同じ座標の組を使い回す**(座標をキーにスロットが決まり、解放されないため)。

```
y=0   ┌──────────────────────────────────────┐ R1 ヘッダ背景(0,0,320,28)
      │ T1 パンくず(8,7)          T2 状態(214,7) │
y=28  ├──────────────────────────────┬───────┤ R2 本体背景(0,28,320,212)
y=32  │ R3/T3  行 0(4,32,270,24)      │R9/T9 ^│
y=58  │ R4/T4  行 1                   │(280,32 │
y=84  │ R5/T5  行 2                   │ 36,76) │
y=110 │ R6/T6  行 3                   │R10/T10│
y=136 │ R7/T7  行 4                   │   v   │
y=162 │ R8/T8  行 5                   │(280,112│
y=188 │                               │ 36,76) │
y=196 │ R11/T11  R12/T12  R13/T13  R14/T14    │ ボタン 4 個(各 74×40、x=4/83/162/241)
y=240 └──────────────────────────────────────┘
```

| スロット | Menu | Session 一覧 | Session 画面 |
|---|---|---|---|
| R1 / T1 | ヘッダ / `Menu` | ヘッダ / `Session` | ヘッダ / `Session > S02` |
| T2 | 再生中なら `>S02 B3`、無ければ BPM | 同左 | `120bpm B3/8` |
| R2 | 本体背景 | 同左 | 同左 |
| R3〜R8 / T3〜T8(6 行) | `Session` / `Song (Phase 19)` / 残りは空 | Session 一覧(`S01 Intro 4bar 4/4`) | Bar 一覧(`> 3  [7/8]`) |
| R9, R10 / T9, T10 | 背景色・空文字 | `^` `v`(スクロール) | `^` `v`(スクロール) |
| R11〜R14 / T11〜T14 | 背景色・空文字 | `BACK` `BPM-` `BPM+` `OPEN` | `BACK` `1:OFF` `RPT:OFF` `PLAY` |
| **合計** | | **rect 14 / 16、text 14 / 16** | **rect 14 / 16、text 14 / 16** |

- **使わないセルの消し方**: rect は本体背景色で塗り、text は空文字にする(スロットは保持されたまま何も描かない)。
- **再生中マーカーと選択カーソルの描き分け(spec §5.3)**:
  - **選択カーソル = 行の背景色**(rect の色だけを変える。スロットは増えない)
  - **再生中マーカー = 行テキストの先頭の `>` を拍に同期して点滅**させる(拍頭から半拍だけ表示)
  - 両者は別の手段なので、同じ行に同時に出ても区別できる
- **トグルの状態** = ボタンのラベルと色(`1:ON` は緑、`1:OFF` は灰)。
- **重なり順の規則(P3)**: `app_init` で**全 rect を先に作り、次に全 text を作る**。以後は同じ座標を更新するだけで新しい座標を使わないので、作成順は起動時に固定され、両ホストで同じ重なりになる。
- **スクロール**: 6 行ずつ表示し、`^` `v` で 1 行ずつ動かす(mp3player と同じ操作)。16 小節の Session は 3 画面ぶん。自動追従はしない(指で見ている位置を奪わないため)。再生中の小節は常にヘッダ T2 に `B3/8` で出る(spec §5.3「画面外の再生中要素はヘッダにインジケータ」)。
- 残りのスロット(rect 2 / text 2)は予備として残す。

### 0-2. 操作設計(指示書 b)

| 画面 | 操作 | 動作 |
|---|---|---|
| Menu | 行 `Session` をタップ | Session 一覧へ(`Song` は Phase 19 まで無効表示) |
| Session 一覧 | 行をタップ | 選択(背景色)。**選択中の行をもう一度タップ、または `OPEN`** で Session 画面へ |
| | `BPM-` / `BPM+` | Transport の現在テンポを ±1(長押しで連打加速。metronome と同じ)。再生中なら次の小節境界から効く |
| | `BACK` | Menu へ(**再生は止まらない**) |
| Session 画面 | 行をタップ | 小節を選択(トグル `1` の対象)。**選択のみ**(spec §5.3) |
| | **行を 600ms 長押し** | **再生中: その小節へ次の小節境界でジャンプ**(`QueuedAction::JumpBar`)。停止中: タップと同じ |
| | `1:ON/OFF` / `RPT:ON/OFF` | トグル。再生中なら次の小節境界から効く(下記の締め切り規則) |
| | `PLAY` / `STOP` | 再生 / 即時停止。別の Session を再生中に `PLAY` したら、止めてから始める |
| | `BACK` | Session 一覧へ(再生は止まらない) |
| どこでも | 電源キー短押し(ホーム) | アプリ終了。ホストが停止する(0xFC) |

決定(承認をお願いしたいもの):

- **Q5(ジャンプ操作の UI)= 行の長押し(600ms)。** ボタンを足すとスロットが足りなくなり、タップ = 選択と自然に両立する。
- **Q6(カウントイン)= v1 には入れない。** 入れるなら「Start 前にクリックだけ鳴らす小節」をどう MIDI Clock と揃えるか(SL MK3 に 1 小節ぶん余計に進ませるか)の設計が要る。Phase 19 の end-to-end で必要性を見てから判断する。
- **Session scope の PC = 再生開始時に即時モード(+64 なし)で送る**(`hostapi_midi_send` で `transport_start` の前)。繰り返しでは送らない。
  - spec §4.2 は Song scope のみとしているので、**仕様からの逸脱**になる。
  - 理由: SL MK3 を別の Session のまま Session 画面から再生すると、パターンとクリックが合わない。
  - 送らない場合は、Session 画面で再生するたびに SL MK3 側を手で合わせる運用になる。
- **テンポの変え方 = Session 一覧の `BPM-` / `BPM+`**(Transport の現在テンポは全 Session で共通なので、一覧に置く)。範囲は 40〜240(metronome と同じ)。

### 0-3. 時間軸の設計(L2、指示書 c)

- **song tick は再生開始で 0 から単調に進むタイムライン**として使い、`locate` / `set_loop` は使わない(Phase 16 の前提)。
  繰り返し・ジャンプ・トグルは「次の小節に何を積むか」が変わるだけ。
- **再生開始**:
  1. 再生中なら `transport_stop`
  2. `tempomap_clear`
  3. `set_tempo(0, upq(bpm))` / `set_meter(0, 最初の小節の拍子)`
  4. (決定どおり)即時 PC
  5. `transport_start`
  6. 小節 0 と小節 1 を積む
- **先読みは「今鳴っている小節の次の 1 小節」まで**(horizon = 1 小節)。
  - 小節 N が始まったことを app_tick で検知したら、小節 N+1 を積む:
    - クリック(拍ごと、1 拍目はアクセント)
    - 小節 N+1 の頭の `set_tempo` / `set_meter`(**変化の有無にかかわらず毎回書く**)
    - 自然終了なら `OP_STOP`
  - **小節 N+1 の開始 tick は小節 N の長さで決まり、トグルやジャンプでは動かない。** 積み直しは「`seq_flush_after(N+1 の開始)` + 同じ at_tick へのテンポ / 拍子の上書き」で済み、**古い予約が別の tick に残ることがない**(horizon を 2 小節以上にするとこれが崩れる)。
  - マップの消費は小節あたり 2 件。畳み込み(Phase 17)が効くので長時間でも枯渇しない。
- **締め切り規則(`docs/results/phase16.md` 残課題)**: トグル・ジャンプ・BPM の変更を受けたとき:
  - 小節 N+1 の開始まで **GUARD = 150ms 以上**残っていれば、N+1 を積み直して**次の境界から**効かせる
  - 残っていなければ、**その次の境界から**効く(N+1 は変更前の内容で鳴り、N+2 を積むときに反映される)
  - GUARD は app_tick の周期(100ms)にジッタの余裕を足した値。最短の小節(240bpm の 2/8 = 250ms)でも成立する
- **計画ロジックは seqcore に置く(ステップ 1)**。ホスト非依存で、Linux の `cargo test` で検査できる。
  - 追加する公開 API(案): `seqcore::timeline`
    - `ticks_per_bar(meter)` / `ticks_per_beat(meter)`(PPQN 960)
    - `BarPlan { start_tick, meter, bpm, beats, stop_at_end }` と、`Transport` と `Bank` から次の小節の `BarPlan` を作る `plan_next(&Transport, &Bank, start_tick)`(`advance_bar` の複製による peek を内部で使う)
    - `Planner`(現在の小節と次の小節の 2 つを保持し、`on_bar_started` / `replan_next_if_before(deadline)` を持つ)
  - 既存 34 テストは変更しない。seqcore の既存公開 API は変えない(追加のみ)。
  - アプリは `Planner` の結果を `seq_write` / `tempomap_*` / `midi_send` に写すだけにする。
- **画面遷移しても再生は止まらない**。Transport と Planner はアプリの静的状態で、画面は覗く窓(spec §4)。
- **再生中の表示**: `get_position` の song tick から「今の小節」を Planner の 2 小節の範囲で決め、行の点滅とヘッダ T2 を更新する。停止は `get_position().state` で知る(`OP_STOP` による自然終了を含む)。

実機の操作手順(ユーザーに依頼する):

- **T1**: Menu → Session → S02 を開く → 戻る → S06 を開いて `v` でスクロール → 戻る(前の画面の残骸が残らないこと)
- **T2**: S02 で `1:OFF` `RPT:OFF` のまま PLAY → 8 小節で自然に止まる(8 小節目は 2 拍)
- **T3**: S02 で `RPT:ON` → 繰り返す → 途中で `RPT:OFF` → その周の最後で止まる
- **T4**: S02 で 3 小節目を選択、`1:ON` `RPT:OFF` で PLAY → 3 小節目だけ鳴って止まる
- **T5**: `1:ON` `RPT:ON` → 3 小節目を繰り返す
- **T6**: 再生中に別の小節を長押し → 次の小節境界でその小節へ移る
- **T7**: S04 を再生(3/4 と 7/8 のクリック数とアクセント)。再生中に BACK で一覧へ → 再生が止まらない、ヘッダに位置が出る
- **T8**: 一覧で `BPM+` を長押し → 次の小節からテンポが上がる

### 0-6. U-2(反復リーク判定)の設計(指示書 f)

- `scripts/device-regress.conf` に `REPEAT_RUNS=3`(既定)と `REPEAT_OVERRIDE[seq_smoke]=1` を足す。seq_smoke は 1 回 60 秒なので繰り返さない。
- 各アプリを N 回「run → hold → stop」する。各回の既存判定(開始→終了の差分 +0)に加え、**N 回の終了時 `free_int` / `free_psram` がすべて同じ値**であることを判定に足す(1 回ごとの差分が 0 でも、開始値自体が回を追って下がる漏れを捕まえる)。
- 表に「反復 N / 終了 free_psram の最小〜最大」の列を足す。所要時間の増加は約 2 分(6 秒保持 × 2 回 × 5 本 + 起動待ち)。
